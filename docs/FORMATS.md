# 形式と解析ルールの詳細

`ichigo_archiver.py` が Wayback の保存ページをどう読み、どうレスにまとめているかの資料です。
パーサを直すときや、うまく取れないページを調べるときに参照してください。
生 HTML は `captures.raw`（gzip）にすべて残っているので、ルールを直したら `parse --all` で作り直せます。

## 1. URL → スレ（`thread_key()`）

経済板のスレ番号は、システムやドメインが変わっても引き継がれています
（例: Aska 時代の `vi=0126` と 15bbs の `economy/0126` は、スレタイも >>1 も同じ）。
そのため、どの形の URL も `economy/NNNN`（4 桁）にまとめます。

| URL の形 | 例 | thread_key |
|---|---|---|
| 15bbs | `/cgi/15bbs/economy/0126/`、`/0126/L50`、`/0126/1-70`、`/0126/194-`、`/0126/80` | `economy/0126` |
| Aska 系 CGI | `readres.cgi?bo=economy&vi=0126`（`rr=` `rs=` `re=` `rm=` 付きも）| `economy/0126` |
| まとめログ | `index.php?k=006&c=000&thread=1162&no=508` | `economy/1162` |
| 住人の過去ログ保存 | `rssnbl.tripod.co.jp/0648.html`、`/0623old.html` | `economy/0648` |
| スレ一覧など | `aska_list.cgi?bo=economy`、`/economy/index.html`、まとめログのトップ・一覧 | なし（NULL）|

- `www.` の有無、`:80` 付き、ホスト違い（`matari.` など）は区別しません
- Wayback には `&amp;` や `&amp;amp;` のまま保存された URL もあるので、`html.unescape` を最大 3 回かけてから解析します
- まとめログの `k=`（コテハン番号）と `c=`（カテゴリ）は絞り込みの状態でしかないので、キーに含めません

### 収集対象（`TARGETS`）

| ホスト | CDX の引き方 | 絞り込み |
|---|---|---|
| `ichigobbs.net`（`www.` `matari.` など含む）| domain | URL に `economy` か `keizai` |
| `ichigobbs.com` / `ichigobbs.org` | domain | 同上 |
| `www22.big.or.jp/~15ch/` | prefix（共用サーバなので、そのパス以下だけ）| 同上 |
| `ichigobbs.ath.cx` | domain | `index.php` |
| `rssnbl.tripod.co.jp` | domain | `/NNNN.html`（4 桁。10 桁の名前は megabbs のスレなので対象外）|

ichigobbs.net は全板が同居しているため、`15bbs` で絞ると他の板（音ゲー板など）まで大量に入ります。
Amazon 関連商品ウィジェット（`/tool/jc/jc.cgi`）は除外しています。

## 2. HTML の形

### 2.1 Aska 系 CGI と 15bbs（2000〜2014）

どちらも同じ系統のスクリプトです（15bbs のフッタは `2ch-Type BBS Ver.2.11+07` と作者サイト「A round」、
背景画像名は `aska_th_bg.gif`）。文字コードは Shift_JIS（`cp932` で読む）。

```html
<DL><B><FONT color=red size=+1>スレタイ</FONT></B>　 <font …>(ログ容量 : 162,443 バイト)</font><br>　<DT>
<dl><dt>01: <font color="forestgreen"><b>名前</b></font>　 2000/11/29(Wed) 17:32<dd>本文<br>本文
<br>　<dt>02:  <font color="forestgreen"><b><a href="mailto:sage">名前</a></b></font>　 2000/11/29(Wed) 17:47<dd>本文
```

- **名前と日付の間に区切り記号がない**。`：` や `:` で分割すると時刻の `17:32` で割れてしまうので、
  日付を正規表現 `DATE` で先に見つけ、その前を名前、後ろを ID・トリップとみなします
- **スレタイ行に閉じない `<DT>` がある**。見出し部分が別の `<dt>` をまたがないようにしています（`DT` の `(?:(?!<dt).)*?`）
- メール欄は名前の `<a href="mailto:…">`。`sage` やひとことに使われることも多い
- スレタイは `<font color=red>`（`parse_title()`）

後期に日付の右へ、背景と同じ色で付くもの:

```html
<dt>911:  <font color="forestgreen"><b>コテハン</b></font>　 2009/05/12(Tue) 09:27　<tt><font color="#eebbee">ID:wWxUqj5PRwac </font></tt>　<tt><font color="#efefef">[ tr.t4dJfuU ]</font></tt><dd>
```

| 表示 | 意味 | 列 |
|---|---|---|
| `[ tr.t4dJfuU ]` | **トリップ**（画面上は背景と同色で見えない）| `posts.trip` |
| `ID:wWxUqj5PRwac` | **ID**（2009年5月から）| `posts.uid` |

削除・移動されたレスは、日付の位置に文言が入ります。この場合は `<b>` の中を名前、後ろの文言を `date` に入れます。

```html
<dt>581:  <font color="forestgreen"><b>いちごJam削除</b></font>　 いちごJam削除　<tt>…[ XqoYFdGy3o ]…</tt><dd>
<dt>260:  <font color="forestgreen"><b>引越しさん</b></font>　 移動されました<dd>
```

### 2.2 まとめログ（ichigobbs.ath.cx、2009〜2019）

「いちごＢＢＳまとめログ」。経済板の過去ログを、常連コテハンごとに見られるようにしたミラーサイト。文字コードは EUC-JP。

```html
<H1>…いちごＢＢＳまとめログ…</H1> …
<A HREF="index.php?k=001&c=000">ドラエモン(15378)</A> - … - <B>cloudy(881)</B> - …   ← コテハン一覧（選択中は太字）
<BR><BR><B>経済板ロビーVol.22</B><BR><BR>                                              ← スレタイ
<DL><DT><A NAME="327">327</A> 名前：ドラエモン 投稿日：2008/10/27(Mon) 20:05</DT><DD><BR>本文</DD></DL>
```

- 番号の後に `：` がなく、`名前：` `投稿日：` のラベルが付く。ラベルは取り除きます
- `<H1>` はサイト名なので、スレタイは本文直前の `<B>…</B><BR><BR><DL>` を先に見ます
- スレ表示ページには、URL の `no=` のレスとその手前 10 件ほどが載ります

一覧ページ（トップ、`md=view`、`md=ts`）の各項目:

```html
<LI><A HREF="index.php?k=006&c=000&thread=1458&no=353#353">スレタイ No.353</A> [2009/05/20] <B>cloudy</B> 抜粋… (1)</LI>
```

ここから次の 3 つを取り込みます（`parse_matome()`）。

| 取り込むもの | 出どころ | 保存先 |
|---|---|---|
| コテハン番号・名前・投稿数 | どのページにもあるコテハン一覧 | `handles`（新しいスナップの投稿数を採用）|
| どのレスが誰か | 一覧項目の `k=`（全体一覧では名前→番号で引く）、スレ表示 URL の `k=` と `no=` | `post_handles` |
| スレタイ | 一覧項目の「スレタイ No.N」 | `threads.title`（本文未取得のスレにも付く）|

この「まとめログ掲載」は、まとめログの判定だけを使います。名前欄が同じだけのレスには付けません（なりすましがあり得るため）。

### 2.3 住人の過去ログ保存（rssnbl.tripod.co.jp）

当時のいちごのページを Internet Explorer で丸ごと保存したもので、形は 2.1 と同じです。先頭に
`<!-- saved from url=(0062)http://matari.ichigobbs.com/cgi/readres.cgi?bo=economy&vi=0648 -->` と元の URL が残ります。

IE は保存時に、長い行を空白の位置で折り返して改行と字下げを入れています（`＞63:⏎    すりらんかさん`）。
HTML ではソース中の改行は空白 1 つで、改行になるのは `<br>` だけなので、`saved from url=` のあるページでは
解析の前にソースの改行と前後の空白を空白 1 つにします。また、どの出どころでも名前と日付の中の改行・連続空白は 1 つにそろえます。

### 2.4 dat 形式

`名前<>メール<>日付 ID<>本文<>タイトル` の行が見つかれば、予備としてその形でも読みます（今のところ該当ページはありません）。

## 3. 同じレスが複数あるとき

同じスレの同じレス番号は、多くのスナップショットに重複して載っています。次の順で 1 つを採用します。

1. **本文が長い方**（1 レスページには >>1 の抜粋が途中で切れた形で載るので、短い方は欠けている可能性がある）
2. 同じ長さなら**古いスナップの方**。後年の ichigobbs.org のログには、名前が既定の名無しに置き換わったものがあるため
   （例: 2004 年の保存では「赤い眼鏡」、2013 年の保存では「名無しさんの冒険」）

この規則は解析の順番に依存しないので、`fetch` / `parse` をどの順で回しても同じ DB になります。
また、壊れたログに混ざる NUL などの制御文字は、解析時に取り除きます（`clean()`）。

## 4. 中身がないページ（`captures.parsed = -1`）

| 種類 | 見分け方（`JUNK`）|
|---|---|
| いちごの「スレッド表示エラー」（過去ログ送り・削除の後）| `<title>` に「スレッド表示エラー」 |
| 15bbs 移行後に旧 `readres.cgi` が返す転送ページ | `<meta http-equiv="REFRESH" content="0;URL=/cgi/15bbs/…">` |
| ドメイン失効後の駐車ページ | `top.location="…?fp=…"`、`data-adblockkey=` |
| プロバイダのエラーページ | `Error. Page cannot be displayed` |

レスに分解できず、上のどれでもないページ（スレ一覧など）は `pages` に全文を保存します。

## 5. 取得の順番（`fetch_order()`）

未取得の URL を、新しいレスが取れる見込みの高い順に 4 段に分けます。
並び順は実行時点の DB から計算するので、`fetch` と `parse` を交互に回すのが効率的です。

| 段 | 中身 | 段の中の順 |
|---|---|---|
| 0 | レスがまだ 1 件もないスレ | 各スレ 1 本目（下の優先度が良いもの）→ 2 本目 … |
| 1 | 欠けを埋めうる保存 | まだ埋まっていない欠けを一番多く含むものから 1 件ずつ選ぶ（貪欲法）|
| 2 | 持っているレスしか載っていない見込みの URL、スレ一覧 | 優先度順 |
| 3 | 中身がない見込み | 優先度順 |

URL ごとの優先度（`fetch_priority()`、小さいほど良い）:

| 優先度 | URL |
|---|---|
| 0 | スレ全体（`/economy/0126/`、`readres.cgi?…&vi=0126` だけ）|
| 1 | 範囲指定・N 以降（`/1-70`、`/194-`、`rs=` `re=`）|
| 2 | 最新 N 件（`/L50`、`rm=`）、まとめログ、一覧 |
| 3 | 1 レスだけ（`/80`、`rr=`）|
| 8 | CDX 上のサイズが 1,000 バイト未満（転送ページは 400 バイト台）、または 5 個以上の URL で中身（digest）が同じ（エラーページ）|
| 9 | ドメインの運用終了後のスナップ（`HOST_END`）|

「欠けを埋めうるか」は、URL から読めるレス番号の範囲（`url_post_range()`）と、**保存日時**で判定します。

| URL | 範囲 |
|---|---|
| `/0014/80`、`rr=291` | その 1 レス |
| `/0040/1-70`、`rs=76&re=77` | 範囲 |
| `/0201/194-`、`rs=50` | その番号以降 |
| まとめログの `no=326` | 316〜326 |
| スレ全体 | 読めない → 保存日時までに書かれた欠けだけ |
| `/L50`、`rm=30` | 読めない → 保存時点の最後の 50（30）件に当たる欠けだけ（`latest_n()`）|

- **欠け**：「スレ内で見つかっている最大番号までの抜け番号」と「1 レスページ由来で、抜粋として切れている可能性のあるレス」。
  スレの長さは、持っているレスの最大番号と、URL に出てくるレス番号の最大から見積もる
- **欠けの投稿日時**：わからないので、直前の既知のレスの投稿日時を下限とする（`post_ts()`）。保存日時がそれより前なら、その保存には載らない
- **保存時点の最後のレス番号**：投稿日時が保存日時以前の既知のレスの最大番号で見積もる

- **外れの記録**：取得済みの保存（レスが取れたもの）それぞれについて、同じ規則で「埋めるはずだった欠け」を計算し、
  その欠けがまだ埋まっていなければ外れ 1 回と数える。`MISS_LIMIT`（2）回外れた欠けは Wayback に無いとみなして候補から外す。
  外さないと、同じ欠けを載せうる保存が何件もあるとき、それを 1 件ずつ全部試すまで段 1 がなくならない
  （貪欲法は 1 件だけ選び、残りを「選んだもので埋まる見込み」として段 2 に回すため、外れると次の 1 件が段 1 に上がってくる）。
  DB に記録は持たず、取得済みの保存と今の欠けから毎回計算する
- この判定は取得先を区別しないので、**新しい保存先を収集対象に加えたとき**は、そこにしかない欠けも「外れ済み」で
  段 1 に上がらないことがある。その場合は `fetch --match 新しいホスト` でその保存先だけをまとめて取る

最初は「範囲が読めない保存は、欠けのあるスレなら全部候補」としていたため、段 1 が 1 万 6 千件にふくらみ、
埋まる見込みのない同じスレの古い保存を取り続けていました（2026-09-30 に修正。候補は 170 件前後になった）。

## 6. スパム（`is_spam()`、`posts.spam = 1`）

次のどれかに当たるものをスパムとします。経済板なので「loan」や「ｗｗｗ＋URL」は普通の書き込みにも多く、判定には使いません。

| 規則 | 例 |
|---|---|
| でたらめな英字のメールアドレス（ローカル部が英小文字 5〜14 字で、母音が 25% 以下）＋本文に URL | `tviscqmbldq@yahoo.co.jp` |
| 本文に定型語（`payday` `airfare` `viagra` `cialis` `casino`、`\|\|\|http://`）| payday loan、ブランド品の羅列 |
| メールアドレスのドメインに `outlet` | `…@cheappradaoutlet.us` |
| **2012 年以降**の書き込みで、URL とブランドコピー語（ブランドコピー、ヴィトン、シャネル、グッチ、プラダ、ロレックス など）| 2014 年のブランド宣伝 |

ブランド語を 2012 年以降に限るのは、それ以前だと「腕時計」「discount」などがニュースの引用や用語（hyperbolic discounting）に出てくるためです。
スパムは主に 2010 年 2 月（payday loan など）と、板がほぼ放置された 2013〜2014 年（スレ 1603・1605 に集中）に来ていました。

## 7. アンカー（`anchors()`）

`show` と閲覧用 HTML のポップアップで使います。DB には保存せず、表示のたびに本文から読みます。

| 書き方 | 読み取り |
|---|---|
| `>>554`、`＞＞５５４`、`≫554`、`>51`、`＞５５５` | 554、51、555 |
| `>>315-316`、`>>1〜3` | 315・316、1〜3 |
| `>>1,3,5`、`>>1、3` | 1・3・5、1・3 |
| `>>100-900`（31 件を超える範囲）| 先頭の 100 だけ |

## 8. 配布用 HTML の形式（`ichigo-archive-1`）

`export-html` と `release` が書き出す HTML です。見た目は掲示板風のまま、`build_posts_db.py` が読めるように
情報を埋め込んでいます。

```html
<html lang="ja" data-format="ichigo-archive-1">
<meta name="thread_key" content="economy/0126"> … <h1>スレタイ</h1>
<dl>
<dt id="556" data-date="2002/05/18(Sat) 18:03" data-uid="…" data-trip="…" data-k="001">556 ：<b>ドラエモン</b>［ドラエモン］：2002/05/18(Sat) 18:03 …</dt>
<dd>本文（改行は <br>、>>アンカーは <a class="anc" href="#554" data-to="554">）</dd>
```

- ファイル構成: `index.html`（トップ。年ごとのリンクとコテハン一覧の表）、`year_YYYY.html`（その年に立ったスレの一覧。
  スレの年は取れている一番古いレスの日付）、`economy_NNNN.html`（スレ 1 本）。`build_posts_db.py` は
  `thread_key` の meta があるファイルだけをスレとして読み、`index.html` からコテハン一覧を読む
- トップと年ページのスレタイ絞り込みは `FILTER_JS`（`tr.t` の `data-title` を見る。全角・半角などは比べるときだけ NFKC でそろえる）
- `data-k` はまとめログのコテハン番号（まとめログ掲載のレスだけ）。番号と名前・投稿数は `index.html` の `<table id="handles">` にある
- 本文は `<br>` を改行に、タグを外して `html.unescape` すれば元に戻る
- スパムとメール欄は書き出さない。`release`（と `export-html --mask-email`）では本文中のメールアドレスを伏せる
- `release` の zip から `build_posts_db.py` で作った DB は、手元の DB（スパムを除く）と、伏せたメールアドレス以外すべて一致することを確認済み

## 9. 既知の限界

- **表記ゆれはそろえずに残している**（2026-10-01 の判断）。特に、同じ文字が読み込んだ元の文字コードで別の文字になる:
  掲示板本体（Shift_JIS）の「～」「－」は U+FF5E・U+FF0D、まとめログ（EUC-JP）の「〜」「−」は U+301C・U+2212。
  例: 「だな～」と「だな〜」、「プロボーラ－」と「プロボーラ−」。検索するときは両方の形で探す必要がある
- まとめログのコテハン登録名が、掲示板上の名前と違うことがある（例: 登録名「プロボーラ」、名前欄は「プロボーラー」）。
  まとめログ掲載はまとめログの判定で付けているので影響はないが、閲覧用 HTML の［ ］は登録名で表示される
- Wayback に一度も保存されなかったスレ（スレ番号 1〜1678 のうち 500 本以上）は取れません
- 1 レスページにしか残っていないレスは、同じページの >>1 の抜粋が切れた形で入ることがあります（より長い版が見つかれば置き換わります）
- 名前が既定の名無しに置き換わったログしか残っていないレスは、元の名前がわかりません
- `url_post_range()` はスレ全体や `/L50` の範囲を読めないため、それらは欠けの有無だけで判断しています
