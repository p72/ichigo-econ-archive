# Wayback Machine から集めるということ

このツールがデータを集めている Internet Archive の Wayback Machine の仕組みと、
経済板がどれくらい・どのように残っているかの分析です。
数字は **2026-09-30 時点**（取得 5,034 件、レス 178,625 件の段階）のものです。

## 1. Wayback の 2 つの入り口

### 1.1 CDX：保存の目録

CDX は Wayback の「保存の索引」です。ページの中身を 1 件も取らずに、何がいつ保存されているかを一覧でもらえます。
`enumerate` はこれを使っています。

```
https://web.archive.org/cdx/search/cdx?url=ichigobbs.net&matchType=domain&output=json
    &fl=original,timestamp,statuscode,mimetype,digest,length
    &filter=statuscode:200&collapse=digest
```

1 行が 1 回の保存です。

| 列 | 中身 | このツールでの使い道 |
|---|---|---|
| `original` | 元の URL | どのスレのどのページか（`thread_key()`）|
| `timestamp` | 保存日時（`20041024114855` など）| 取得するときに指定する |
| `statuscode` | 当時の HTTP の応答 | 正常なページ（200）だけに絞る |
| `mimetype` | 種類（`text/html` など）| 画像などを除く |
| `digest` | 中身のハッシュ | 多数の URL で同じ中身＝定型のエラーページ、と見分ける |
| `length` | 保存サイズ（圧縮後）| 400 バイト台の転送ページを見分ける |

- `matchType=domain` はサブドメインも含めて全部、`prefix` はそのパス以下だけ（共用サーバの `www22.big.or.jp/~15ch/` で使用）
- `collapse=digest` は、連続して中身がまったく同じ保存を 1 件にまとめる
- ichigobbs.net は 1 回の問い合わせで約 38 万 7 千行（全板分）が返ってきた。そこから経済板だけを拾っている

目録だけで件数・URL の形・年ごとの保存量がわかるので、**中身を取る前に選別できる**のが強みです。
転送ページ（`length`）やエラーページ（`digest`）の見分けで、1 万件ほどの無駄な取得を避けています。

### 1.2 保存されたページそのもの

```
https://web.archive.org/web/{timestamp}id_/{original}
```

`id_` を付けると、Wayback のツールバーやリンクの書き換えがない、**当時サーバが返したままの HTML** が返ります。
`fetch` はこれを 1 件ずつ、2 秒間隔で取っています。

## 2. 「1 件」とは何か

Wayback では同じ URL が何度も保存されています。このツールでは **URL と保存日時の組を 1 件**と数えます（`captures` の 1 行）。

```
/cgi/15bbs/economy/0702/  2004-06-18 の保存   ← 1 件
/cgi/15bbs/economy/0702/  2004-10-10 の保存   ← 別の 1 件
/cgi/15bbs/economy/0702/L50  2005-03-02 の保存 ← 別の 1 件
```

一度取った保存は二度と取りません。`fetch` は毎回、その時点の DB から各スレの欠けを計算し直し、
まだ取っていない保存の中から「新しいレスが取れる見込み」の高いものを選びます（詳細は [FORMATS.md](FORMATS.md) の 5 章）。
同じ条件なら新しい保存を先に取ります（新しいほどレスが多く載っているため）。

## 3. 上限：74,032 件

わかっている 5 か所（ichigobbs.net / .com / .org、www22.big.or.jp/~15ch/、ichigobbs.ath.cx）について、
URL に `economy`（または `keizai`、まとめログは `index.php`）を含み、正常に保存されたテキストのページは **74,032 件**です。

サイトがもう存在しないので、Wayback に新しい保存が加わることはほぼなく、**この条件のままならこれが上限**です。増えうるのは次の場合です。

- まだ知らない移転先・ミラーが見つかったとき（`enumerate --host 新しい場所`）
- Wayback 以外のアーカイブ（archive.today、国立国会図書館 WARP、個人保存の dat ファイルなど）を使うとき。今のツールの対象外
- URL に `economy` を含まない形で経済板の書き込みが載ったページがあったとき（今のところ見つかっていない）

## 6. なぜ欠けるのか

### 6.1 保存の量が年によって極端に偏っている

ichigobbs.net の経済板の保存件数（CDX の目録から）:

| 年 | 件数 |
|---|---|
| 2002 | 1,732 |
| 2003 | 1,806 |
| **2004** | **25,396** |
| **2005** | **34,740** |
| 2006 | 1,872 |
| 2007 | 1,845 |
| 2008 | 817 |
| 2009 | 397 |

2004〜2005 年の 2 年間だけで 9 割近くを占めます。この時期に集中的な巡回があったようです（事情はデータからはわからない）。

### 6.2 たまの保存も「最新 50 件」ページだった

巡回プログラムはリンクをたどって保存します。15bbs のスレ一覧からのリンクは「最新 50 件（`/L50`）」の形だったので、
巡回の少ない時期は、スレの**最新 50 件だけ**が残りがちでした。欠けの大きいスレの例:

| スレ | 書き込み期間 | Wayback の保存 | 取れたレス / 最大番号 |
|---|---|---|---|
| ★くだらない質問はここに書き込め★16問目（1291）| 2008/04〜11 | 最新 N 件 1 回（2008）、1 レスページ 4 つ（2010）| 35 / 1013 |
| 経済ニュース 11（1287）| 2008/04〜11 | 最新 N 件 1 回（2008）だけ | 32 / 1005 |
| ☆質問してね☆仲良くね☆１４（1240）| 2007/08〜11 | 最新 N 件 各 1 回（2007・2008）| 52 / 1007 |

### 6.3 スレ番号帯ごとの「スレ全体の保存がある割合」

| スレ番号 | スレが立った時期（>>1 の日付の中ほど 8 割）| スレ全体の保存あり |
|---|---|---|
| 0000〜0199 | 2000/08〜2001/02 | 68 / 180 |
| 0200〜0399 | 2001/03〜2001/10 | 56 / 181 |
| 0400〜0599 | 2001/12〜2002/07 | 82 / 176 |
| 0600〜0799 | 2002/10〜2003/07 | 99 / 150 |
| **0800〜0999** | **2003/08〜2004/10** | **143 / 168（85%）** |
| 1000〜1199 | 2005/02〜2006/11 | 85 / 109 |
| 1200〜1399 | 2007/05〜2009/01 | 47 / 94 |
| **1400〜1599** | **2009/03〜2010/02** | **18 / 50（36%）** |

2004〜2005 年の集中的な巡回のときに書き込みが続いていたスレ（0800 番台〜0900 番台）ほど、スレ全体が残っています。
それ以前のスレも、長く続いたものはこの巡回で拾われています。

### 6.4 残りを全部取っても埋まらない：欠けの 98%

欠けているレス番号 1 つずつについて、「まだ取っていない保存の中に、その番号が載りうるページがあるか」を調べた結果です。

| | レス数 | 割合 |
|---|---|---|
| その番号を含む範囲のページ（`/100-150`、`rr=123` など）が未取得で残っている | 327 | 1% |
| 範囲はわからないが、そのスレのスレ全体・最新 N 件のページが未取得で残っている | 291 | 1% |
| **その番号が載りうるページが、未取得分にも取得済み分にもない** | **31,815** | **98%** |

判定は URL から読めるレス番号の範囲にもとづくので、まとめログの表示範囲の見積もりや、
「中身なし」と推定して後回しにしたページの中に例外はありえます。
それでも、Wayback から埋まりうる欠けは多く見積もって 600 件前後です。

## 6.5 取り尽くしの確認（2026-10-01）

取得順を「保存日時で絞り、貪欲法で選ぶ」方式に直してから、段 1（欠けを埋めうる保存）を読み続けた結果:

| | 取得 | 増えたレス |
|---|---|---|
| 最初の 183 件（段 0・段 1）| 183 | +288 |
| 続く 10 回 | 約 590 | +411 |
| さらに 8 回（3 回続けて +0 で停止）| 約 260 | +4 |
| 最後の 26 件 | 26 | +0 |

最後は「載せうるはずの保存を読んでも出てこない欠け」ばかりになったので、2 回外れた欠けは候補から外す判定を入れた。
これで段 1 は 0 件になり、**わかっている保存先の Wayback から取れるレスは取り尽くした**（レス 180,151 件、取得 7,371 / 74,493 件）。

## 7. まとめログ（ichigobbs.ath.cx）は全部のミラーではない

- まとめログのコテハン 21 人の投稿数の合計は **ちょうど 26,108 件**で、トップの「全て(26108)」と一致する。
  つまりまとめログは、**常連コテハン 21 人の書き込みを集めたサイト**で、板全体（推定 20〜30 万レス）の 1 割前後しかカバーしていない
- スレ表示ページには、指定したレスの手前 10 件ほどが文脈として一緒に載る
- Wayback に残っているまとめログのページは 1,033 件（スレ表示 843 件、179 スレ）。**964 件が 2016 年**の 1 回の巡回
- それでも、1 レスページしかないスレの穴埋めや、「まとめログ掲載」（どのレスがどのコテハンのものとしてまとめログに載っていたか、`post_handles`）の出どころとして役に立つ
